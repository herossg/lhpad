# LHPad 1.1.2 — Windows 환경별 탐색기 메뉴 중복 방지

Windows 11 클라이언트에서는 패키지 방식만, Windows 10/Server에서는 기존 방식만 등록한다. 등록 시 이전 LHPad·LitePad 메뉴를 정리하고, 소유한 실행 파일 또는 소유권 표식으로 확인한 항목만 변경한다. 반복 등록과 제거를 직렬화하고 패키지의 버전·상태·설치 경로를 검증한다. 제거할 때는 한 경로가 실패해도 나머지 정리를 시도한다.

이번 변경과 검증 범위는 탐색기 메뉴 등록에 한정한다. 편집기 기능 검증은 실행하지 않는다.

등록 상태 확인도 Windows 환경에 맞는 메뉴 방식으로 판단한다. 기존 방식의 메뉴가 없다는 이유로 정상적인 Windows 11 등록을 미등록으로 판단하지 않는다. 레거시 키는 소유권 표식 또는 LHPad/LitePad 실행 명령으로 식별하며, 다른 프로그램의 활성 명령은 수정하지 않고 충돌을 알린다. 이전 키의 알 수 없는 값은 남겨 두면서 메뉴 활성화 값만 제거한다.

패키지는 버전·상태·외부 위치와 정상 패키지 개수 1개를 확인한다. 다른 폴더의 같은 버전을 교체하기 전 배포 파일을 확인한다. 등록·제거는 직렬화하며 Windows 11 패키지 실패 시 기존 메뉴를 함께 추가하지 않는다. 설치 도구도 Server 환경 및 새 등록 상태 형식을 인식한다.

이후 등록에는 1.1.2 배포 폴더를 사용한다.

## 등록 검증 (2026-11-09)

- Windows 버전 경계, Windows 10/11 및 Server 분기, 반복 등록/제거, 이전 메뉴 정리, 소유권 충돌/외부 값 보존을 전용 레지스트리 테스트로 확인했다. LHZip 5개·LHPad 6개 항목이 통과했다.
- 현재 Windows 11 데스크톱 세션에서 이전 LHPad 등록에서 새 버전으로 전환, 각 프로그램 반복 등록, 두 패키지 동시 등록, 각 프로그램 반복 제거, 최종 상태 복원을 7단계로 확인했다. 매 단계 기존 방식의 메뉴 등록은 0개였고, 활성화한 프로그램의 패키지는 각 1개·Status=Ok였다.
- 마지막 상태는 LHPad 1.1.2 패키지 1개, LHZip 패키지 0개, 기존 메뉴 등록 0개, LHZip 자동 등록 설정 0이다. 화면 확인은 사용자에게 맡겼으며 메뉴 명령 실행, 압축·해제·편집 기능 테스트는 하지 않았다.
- Windows 10/Server는 이 PC에서 실제 실행하지 않았으며, 버전 판정과 기존 방식 등록을 격리된 레지스트리에서 검증했다.
