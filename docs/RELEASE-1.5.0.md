# LHPad 1.5.0 — 다크 모드

## 추가

- `보기 → 다크 모드`. 첫 실행은 Windows 앱 모드(`AppsUseLightTheme`)를 따르고 이후 선택은 `session.json`의 `DarkMode`로 유지한다.
- **팔레트**: 직접 그리는 모든 색을 `Palette`(core.cpp) 한곳에서 관리한다. 밝은 팔레트는 기존 값 그대로다.
- **편집기**: 기본 글자·배경, 줄 번호·접기 여백, 캐럿·현재 줄, 선택, 공백 기호, 비교 표시를 팔레트로 칠한다. 언어별 색(`stylers.xml`)은 HSL로 같은 색조의 밝은 색으로 바꾸고, 기본 배경 대비 4.5:1(WCAG AA)이 될 때까지 밝기를 더 올린다. 흰색 계열 배경은 편집기 배경으로, 색 배경은 같은 색조의 어두운 색으로 바꾼다. 테마 전환은 색만 다시 칠하므로(`Languages::recolor`) 문서 내용·저장 상태·구문 분석·접힌 구간이 그대로다.
- **메인 창**: 제목 표시줄(DWM), 메뉴(uxtheme 앱 모드, Windows 10 1903 이상), 메뉴 표시줄(UAH 그리기 메시지), 툴바 배경과 눌림·강조 상태, 탭, 상태 표시줄, 검색 결과·함수 목록 패널, 편집기 스크롤바.
- **툴바 아이콘 어두운 세트**: 투명 바탕 위의 선(화살표, 손잡이, 줄)만 밝게 바꾼 `<이름>-dark-<px>.png` 150개를 추가했다. 파스텔 면 위의 세부는 원래 색을 유지해 어두운 배경에서도 모양이 그대로 보인다.
- **Hex 보기**: 바탕, 머리글, 주소, 선택, 변경 바이트, 데이터 검사 영역을 팔레트로 칠한다.

밝게 남는 부분: 찾기 창, 설정·입력 창, 정보 창, 메시지 상자, 비교 창 테두리, 탭이 넘칠 때의 좌우 화살표. 미리보기는 문서가 지정한 색을 그대로 쓴다.

## 검증

- `stylers.xml`의 모든 언어 스타일 1,773개를 같은 공식으로 계산했다. 기본 배경 위의 글자는 모두 대비 4.5:1 이상이며 중간값은 7.7:1이다. 3:1 미만은 원래 색 배경을 지정한 특수 스타일 14개(ANSI 이스케이프 색, XML 사용자 속성 강조)뿐이다.
- `--self-test`에 다크 모드 전환(편집기 배경, 키워드 색 밝기, 문서·저장 상태·구문 스타일 유지, 패널 색, 메뉴 체크, 순수 파랑·빨강 대비 4.5:1, 끄면 원래 색 복원) 검사를 추가했다. 자체 테스트는 `--demo` 모드로 실행되어 Windows 설정과 관계없이 밝은 모드에서 시작한다.
- MinGW-w64(GCC 13) `-fsyntax-only -Wall -Wextra -Wshadow`로 변경 파일 문법을 확인했다.
- 2026-11-19 Windows 11에서 `./build.ps1 -Test` (MSVC) 빌드 성공. 네이티브 자체 테스트 219개 전체 통과(다크 모드 8개 포함), 탐색기 메뉴 회귀 테스트 통과, 서명 5개 Valid, 배포 폴더에 툴바 아이콘 300개(밝은·어두운 세트) 포함.
- 첫 두 번의 실행은 테스트 기준 오류로 실패했다: 키워드 색을 체감 밝기 140 초과로 판정(실제 대비 4.84:1로 충족), `int`를 키워드로 가정(Notepad++ 데이터에서 type1). 두 검사를 대비율과 `return` 위치 비교로 고쳤다. 앱 코드는 바뀌지 않았다.
- 같은 PowerShell 창에서 반복 빌드하면 `vcvars64.bat`가 PATH를 늘려 cmd 한도를 넘는 문제가 있어, 이미 로드된 MSVC 환경은 재사용하도록 `cpp/build.ps1`을 고쳤다.
- 메뉴 표시줄·제목 표시줄·탭·상태 표시줄의 실제 모양은 화면에서 확인해야 한다.
