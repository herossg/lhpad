# LHPad 1.6.0 — 자동 완성

## 추가

- 단어 문자(영문·숫자·`_`·한글 등 UTF-8 문자)를 입력해 현재 단어가 설정한 글자 수(기본 3) 이상이 되면 Scintilla 자동 완성 목록을 띄운다. `Ctrl+Space`(편집 → 자동 완성 목록)는 한 글자부터 띄운다.
- 후보: 문서 앞 8 MiB의 3~80바이트 단어(숫자로 시작하는 토큰 제외) + 현재 언어의 Notepad++ 키워드(`langs.xml`의 모든 `Keywords`). 대소문자를 구분하지 않는 순서로 최대 500개, 입력한 단어와 똑같은 항목은 뺀다. 단어 목록은 문서별로 캐시하며 문서가 바뀐 뒤 1.5초가 지나야 다시 읽는다(키마다 전체를 다시 읽지 않기 위해).
- 목록이 떠 있을 때 Enter는 줄바꿈·자동 들여쓰기 대신 선택 항목을 넣는다. Tab도 넣고 Esc는 닫는다. 일치 항목이 없으면 목록이 자동으로 닫힌다.
- 여러 커서, 로그 모니터링, 200 MiB 초과 대용량, 매크로 실행 중에는 띄우지 않는다. 매크로 녹화 중에는 자동으로 띄우지 않는다(화살표 키가 목록에 쓰여 녹화 내용이 화면과 달라지는 것을 막기 위해). `Ctrl+Space`는 동작한다.
- 툴바 버튼과 `편집 → 입력할 때 자동 완성`으로 바로 켜고 끈다(켜져 있으면 버튼이 눌린 상태). 아이콘은 같은 SVG 규칙으로 추가했다(`AutoComplete`, 밝은·어두운 세트).
- `도구 → 설정`: 입력할 때 자동 완성 목록 표시(`AutoComplete`), 시작 글자 수 1~10(`CompleteMinChars`). 세션에 저장한다.
- 다크 모드에서 목록 색(글자, 배경, 선택)을 팔레트로 칠한다.

## 검증

- `--self-test`에 문서 단어 후보, `Ctrl+Space`, 최소 글자 수, Enter로 넣기(줄바꿈 대신), C++ 키워드, 한글 단어와 숫자 제외, 끄기, 녹화 중 억제 검사를 추가했다. 기존 키 입력 테스트가 목록에 영향받지 않도록 자체 테스트는 자동 완성을 끈 상태로 시작하고 해당 구간에서만 켠다.
- MinGW-w64(GCC 13) `-fsyntax-only -Wall -Wextra -Wshadow`로 변경 파일 문법을 확인했다.
- 2026-11-19 Windows 11에서 `./build.ps1 -Test` (MSVC) 빌드 성공. 네이티브 자체 테스트 233개 통과(자동 완성 10개 포함), 실패 0.
- 실제 마우스로 파일을 끌어 놓는 OLE 드롭 테스트는 다른 앱 창(크롬 계열)이 테스트 창을 가려 한 번 실패했다. 테스트 파일이 다른 앱에 떨어지지 않도록, 드롭 전에 커서 아래 창을 확인하고 가려져 있으면 드롭하지 않고 SKIP으로 기록하도록 고쳤다. 이번 빌드에서는 SKIP으로 기록됐고, 파일 드롭 처리는 탭 영역·편집기 드롭 테스트가 통과로 확인했다.
