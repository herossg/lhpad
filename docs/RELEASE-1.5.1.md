# LHPad 1.5.1 — 대화상자 다크 모드

## 변경

- 찾기 창, 설정·입력 창(파일에서 찾기, 열 편집, 매크로 등), 정보 창, 비교 창이 다크 모드를 따른다. 공용 함수 `themeDialog`(제목 표시줄과 자식 컨트롤 테마)와 `dialogColours`(배경과 `WM_CTLCOLOR*`)를 각 창 프로시저가 함께 쓴다. 밝은 모드에서는 `dialogColours`가 아무것도 처리하지 않아 기존 동작 그대로다.
- 컨트롤: 버튼은 `DarkMode_Explorer`, 입력칸·콤보박스는 `DarkMode_CFD` 테마를 쓴다. 체크박스는 다크 테마에서 글자색 지정이 무시되는 Windows 제약 때문에 클래식 모양으로 그려 글자색을 적용한다.
- 메시지 상자: Windows TaskDialog는 다크 모드를 지원하지 않아, 다크 모드일 때 `messageDialog`(LHPad 자체 창)를 띄운다. 버튼 구성(확인 / 예·아니요 / 예·아니요·취소), 기본 버튼, Esc 결과(예·아니요는 아니요, 확인은 확인)를 시스템 대화상자와 같게 했다. 긴 내용은 스크롤된다. 밝은 모드는 기존 TaskDialog를 쓴다.
- 이미 열린 찾기·비교 창도 다크 모드를 바꾸면 바로 바뀐다.

밝게 남는 부분: 글꼴 선택 창(Windows 공용 대화상자). 열기·저장 창은 Windows 설정을 따른다.

## 검증

- `--self-test`에 다크 메시지 상자 검사 4개(누른 버튼 반환, 어두운 배경, 예·아니요에서 Esc는 아니요, 확인 상자에서 Esc는 확인)를 추가했다. 배경 검사는 화면 픽셀이 아니라 메모리 비트맵에 배경을 그려 확인하므로 다른 창에 가려져도 결과가 같다.
- MinGW-w64(GCC 13) `-fsyntax-only -Wall -Wextra -Wshadow`로 변경 파일 문법을 확인했다.
- 2026-11-19 Windows 11에서 `./build.ps1 -Test` (MSVC) 빌드 성공. 네이티브 자체 테스트 223개 전체 통과(메시지 상자 4개 포함), 탐색기 메뉴 회귀 테스트 통과, 서명 5개 Valid. 사용자가 다크 모드에서 대화상자 표시를 화면으로 확인했다.
